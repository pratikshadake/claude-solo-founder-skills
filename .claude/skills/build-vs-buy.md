# Skill: Build vs Buy Decision Engine

## Purpose
Provide a rigorous, repeatable framework to decide whether a team
should build a solution internally or purchase an external product.

This skill prioritizes:
- speed to value
- long-term strategic leverage
- total cost of ownership
- engineering focus

---

## When to Use
Activate when:

- A new capability is required.
- A SaaS/tool/vendor is being considered.
- Engineers propose building internally.
- Leadership asks: "Should we just build this?"

---

## Required Inputs
If missing, ask the user:

- Problem to solve
- Timeline pressure
- Budget range
- Strategic importance
- Internal engineering capacity

---

## Decision Framework

### 1. Time to Value
Compare:

- Build delivery timeline
- Vendor onboarding time

Flag **high risk** if build time > 2× buy time.

---

### 2. Total Cost of Ownership (TCO)

Include:

- Engineering build time
- Maintenance burden
- Infra costs
- Vendor pricing
- Switching costs

Project over **24 months**.

---

### 3. Strategic Differentiation

Classify the capability:

- Core advantage → lean BUILD
- Commodity → lean BUY
- Experimental → lean BUY fast

---

### 4. Control & Risk

Evaluate:

- Data sensitivity
- Vendor lock-in
- Reliability requirements
- Compliance constraints

---

### 5. Opportunity Cost

Ask:

> What higher-leverage work will NOT happen if we build this?

This is a **critical deciding factor**.

---

## Scoring Model

Produce:

- Build Score (0–10)
- Buy Score (0–10)

Explain each score briefly.

---

## Final Recommendation Rules

- Score difference ≥ 3 → choose higher
- Difference < 3 → recommend **hybrid / phased approach**

Always include:

- Key assumption risks
- Revisit trigger (when to re-evaluate)

---

## Output Format

Return **exactly**:

### Decision
BUILD / BUY / HYBRID

### Rationale
Concise paragraph.

### Scorecard
- Time to value:
- TCO:
- Differentiation:
- Control & risk:
- Opportunity cost:

### Risks
Bullet list.

### Revisit Trigger

---

## Quality Bar

The recommendation must feel like:

> Advice from a seasoned CTO or startup founder  
> not a generic AI summary.
